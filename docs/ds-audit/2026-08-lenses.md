## Lens 3 — State completeness

**Verdict: PARTIAL.** The six `.btn-*` classes own their states properly; almost
everything else re-derives states per call site or lacks them entirely.

### Consequential gaps, ranked

1. **`.task-card` is not keyboard operable** — the app's primary object opens via
   `<div onClick>` (TaskCardView.js:137). A keyboard user cannot open a task.
   Same shape in PortalTaskCard and `.draft-card`.
2. **Drawer has no focus management and leaks tab stops** — children render even
   when closed (Drawer.js:120), so an off-screen drawer stays in the tab order;
   no trap, no initial focus, no restore, no `role="dialog"`.
3. **The shared focus-visible rule (globals.css:99-105) covers exactly six
   selectors** — the `.btn-*` set. Menus, tabs, cards, pills, field triggers and
   all 37 calendar buttons fall back to the UA ring or nothing.
4. **MenuList implements no listbox keyboard model** — `role="listbox"` with no
   arrow keys, no ESC, no focus return; 14 consumers, each re-rolling its own
   outside-click handling.
5. **FieldPill/FieldRow are unfocusable divs** — the drawer's primary editors
   (status, priority, due date, owner) are mouse-only.
6. **Tooltip is hover-only** and `.health-pill` puts the entire health rationale
   behind it with no text fallback.
7. **No loading state in any primitive** (InsightCard's streaming ring is the one
   exception); every call site improvises. No `aria-busy` anywhere.
8. **No error/invalid state anywhere** — zero `aria-invalid`, zero danger-border
   rules in globals.css.
9. **Reduced-motion guards cover the AI shimmer and mobile-blocker but not the
   high-traffic motion** — drawer slide, task-completion animation, checkbox
   bounce are all unguarded.
10. **`.menu-option:hover` omits `:not(:disabled)`** (globals.css:221) — the one
    hover rule that breaks the convention every `.btn-*` rule follows.

## Lens 5 — Enforcement & feedback loops

**Verdict: GAP.** One CI gate exists (unit tests). Nothing enforces a single
design rule; an agent can violate every convention in CLAUDE.md with zero red
lights.

| Check | Exists | Runs where | Covers | Does NOT cover |
|---|---|---|---|---|
| `design.md lint` (`lint:ds`) | ✓ | manual | DESIGN.md schema, contrast, refs | any app code |
| Theme generation (`build:ds`) | ✓ | predev/prebuild | theme.css can't drift from DESIGN.md | the docs describing it (see Lens 6) |
| ESLint | ✓ | manual + PostToolUse edit hook | next/core-web-vitals only | tokens, raw values, DS rules — zero custom rules |
| Unit tests (Vitest) | ✓ | **CI (the only gate)** | 3 pure-logic files | every component |
| Playwright e2e | ✓ | manual only | 2 flows | not in CI |
| Component tests | ✗ | — | — | — |
| Visual regression | ✗ | — | — | — |
| A11y automation | ✗ | — | — | — |
| Lint/build in CI | ✗ | — | — | — |

The one genuinely good pattern: the PostToolUse hook runs `eslint --fix` on every
agent edit — the *pipe* for agent self-correction exists; it just carries no
design signal yet. Phase 3 pours the DS rules into it.

## Lens 6 — Docs & drift

**Verdict: GAP — 52 defects: 19 FALSE · 11 STALE · 5 DEAD · 17 MINOR.**
Full inventory with file:line for both sides of every claim is in the audit
record; headlines:

- **One live CSS bug found, not just doc drift:** `globals.css:25-28` has an
  unlayered `* { margin: 0 }` reset AFTER the Tailwind import. Unlayered rules
  beat `@layer utilities`, so **every Tailwind margin utility (`m-*`, `mt-*`…)
  silently does nothing app-wide.** Both the style-right and tailwind-css-v4
  skills explicitly name this exact pattern as the thing never to do. Same
  mechanism makes `.btn-tertiary`'s `font-weight: 500` beat the documented
  `font-normal` utility.
- **The wrong filename `scripts/build-theme.js` appears in 3 docs plus the
  generated theme.css header itself** — the generator hardcodes the wrong name
  for itself (build-theme.mjs:41). Perfect example of why Phase 9 generates
  docs from code.
- **"Every dropdown MUST use MenuList" appears in 3 docs (one injected into
  every Cursor session) and is violated by 6 components.**
- **DESIGN.md contradicts itself**: line 115 claims `@theme` config exists;
  line 381 lists adding it as a future plan. 266 lines apart.
- **5 dead things**: tokens `--warning`, `--nav-hover`, `--accent-muted`, the
  `primary/secondary/tertiary` alias trio (all emitted, zero usages), and the
  `.task-filter-btn` class.
- **style-right's token table**: 2 stale hexes (`--action-hover`, `--alert`),
  `--text-secondary` missing entirely (making DESIGN.md's core muted→secondary
  hover rule unimplementable from the table), and a stale hover-token rule
  superseded by a decision logged in CLAUDE.md 2026-07-12 but never propagated.
- Assorted FALSE specifics: secondary button bg/border, MenuList bg, shadow
  "only one in the system" (10 sites, 4 values), home grid "7 columns" (8),
  kanban "240px" (264), InsightCard "uppercase" title (isn't), small-label
  "11px" (cited example is 16px).
- **README.md is the most accurate doc in the repo**; the skills — the files
  agents load most — are the least.

## Lens 7 — Agent affordances

**Verdict: PARTIAL — an inverted pyramid.** Judged against the four-layer model
(knowledge should live as far down as possible: token > component default >
lint error > doc):

- **Layer 1 (tokens): exists but unreachable.** Generated, semantic, disciplined
  — but not wired into Tailwind (no `@theme`), so the convenient path is inline
  `var()`; and nothing *bans* raw values, so the tokens are advisory.
- **Layer 2 (components): exists but soft.** 14 primitives, all stringly-typed
  (any `variant` typo silently falls through), no manifests, no stories, 8
  missing primitives forcing call sites off-road.
- **Layer 3 (rules + triggers): exceptional in structure, rotten in content.**
  11 skills, Cursor rules, a 33KB decision journal, an edit hook — the best
  instruction layer most teams never build. But Lens 6 shows the content: 52
  defects, and the skills agents load most are the least accurate.
- **Layer 4 (feedback loops): absent for design.** No check can tell an agent
  it broke the design system.

**The diagnosis in one line: all the system's weight rests on its weakest layer.
Prose is the only carrier of the rules, and prose rots — Lens 6's 52 defects
are the direct, predictable consequence.** The plan is precisely the inversion
of this pyramid: Phase 2 makes tokens reachable, Phases 1/4/5 harden components,
Phase 3 installs enforcement, Phase 9 makes the prose generated so it can no
longer rot.
