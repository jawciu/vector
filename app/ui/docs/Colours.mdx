# Colours

Every colour in Vector is a token defined in `DESIGN.md` and generated into `app/theme.css`
by `npm run build:ds`. Each token is both a CSS variable and a Tailwind utility class
(`bg-action`, `text-muted`, `border-border`). Prefer the utility classes in new code;
`var(--color-*)` works everywhere for CSS and dynamic styles.

The swatches below are painted with `var(--color-*)` directly, so this page can never
drift from the shipped values. To change a colour, edit `DESIGN.md` and rebuild.

## Surfaces

Surfaces stack vertically by elevation: `bg` (page) → `bg-elevated` (cards, modals) →
`surface` (buttons, inputs, pills). Depth comes from background layering, not shadows.
Hover states bump one rung up; active/selected always lands on `surface-hover` regardless
of base.

## AI gradient

Marks output as AI-generated: the Vector sparkle, AI section dividers, hover highlights
on AI-actionable items. `ai-gradient-from` equals `action` lilac; `ai-gradient-to` is a
warm peach. Always a 135deg sweep. For SVG fills, inline the gradient as a
`<linearGradient>` referencing the two stops.

## Focus and scrim

`focus-ring` (equals `action`) is the outline colour for `:focus-visible` on interactive
elements: 2px solid, 2px offset. De-emphasising a control must never cost it a focus
ring. `scrim` is the modal and dialog backdrop (60% black), painted on the native
`<dialog>` `::backdrop` by the Modal primitive.

## Usage rules

From the do's and don'ts in `DESIGN.md`:

- **Layer surfaces for depth, not shadows.** Add a 1px `border` if more separation is
  needed. The only shadow in the system is `shadow-floating` on the bulk action bar.
- **Use `text-secondary` as the hover step** from `text-muted` on navigation surfaces.
  Jumping straight to `text` reads as "selected".
- **Don't use status colours for decoration**, for example `danger` for "important"
  without an actual destructive action.
- **Use the avatar palette for company and contact initials only.** Never for status
  or action.
- **Don't add new top-level CSS custom properties without updating `DESIGN.md`.** It is
  the source of truth; `theme.css` is generated from it.
- A `primary` alias exists in the tokens because the design.md spec requires one. It is
  spec ceremony: use `action` in app code.
