# Typography

Vector sets type in **Geist** (`--font-sans`, with a system-ui fallback) and uses
**Geist Mono** for code-like content such as task IDs. The scale is expressed as the
Tailwind utilities in use: every rung equals Tailwind v4's default, so `text-xs` through
`text-xl` **are** the scale at runtime and no `--text-*` overrides are emitted.

The rows below render with the real utility classes, so the sizes on this page are the
sizes in the product.

## The scale

xl was proposed at 22px; Caroline ruled 20px (2026-08-09), matching Tailwind and the
existing login heading.

<Sample>
  <TypeRow cls="text-xs" px="12px" use="Chips, metadata" sample="Last synced 4 minutes ago" />
  <TypeRow cls="text-sm" px="14px" use="Default UI size, body" sample="Vendors see only the tasks assigned to them." />
  <TypeRow cls="text-base" px="16px" use="Emphasised body" sample="Three tasks are blocked on customer input." />
  <TypeRow cls="text-lg" px="18px" use="Panel titles" sample="Onboarding overview" />
  <TypeRow cls="text-xl" px="20px" use="Page / dialog headings (login Sign in)" sample="Sign in" />
</Sample>

Body sits at `text-sm` (14px) with line-height 1.5.

## Small label

Section headers (for example card titles in InsightsPanel) use the small label treatment:
11px, uppercase, 0.6px letter-spacing. It sits below the scale's `xs` rung and is a
treatment, not a size rung.

- `--font-sans` is the registered token:
  `var(--font-geist-sans), system-ui, sans-serif`. The app loads Geist via `next/font`
  in `app/layout.js`; Storybook maps the same variables in `.storybook/preview.tsx`.
- Geist Mono is loaded by the app as `--font-geist-mono`. It is not yet a registered
  design token in `DESIGN.md` (only the sans stack is).

## Rules

- Reach for the scale's utility classes (`text-xs` … `text-xl`), never arbitrary sizes.
  The `vector/no-arbitrary-tailwind` lint rule flags values that dodge the scale.
- Source copy stays sentence case even when a treatment uppercases the rendered text
  (see Foundations/Voice & copy).
