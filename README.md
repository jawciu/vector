# Vector

Vector is a customer-onboarding workflow platform built around a shared vendor/customer experience, with an AI layer that helps with the tedious work - follow-ups, drafting nudges, creating tasks after meetings, evaluating risks or analysing progress.

## What's in the box

### 1. Vendor workspace
- **Kanban board per onboarding** — phases as columns (Kickoff → Configuration → Data Migration → Training → Go-Live), drag-and-drop via [dnd-kit](https://dndkit.com/).
- **Task model** with status tags, owners, due dates, dependencies (`blockedByTask`), customer-side assignees, comments and file uploads.
- **Portfolio dashboard** — health across all onboardings with AI summary and risk points surfaced.
- **Activity log + notifications** — every status change, comment, upload and link activation, grouped into a vendor inbox.
- **Magic-link invites** customer portal magic link shared via [Resend](https://resend.com), with bounce/complaint webhook handling.

### 2. Customer portal
- Zero-friction magic-link entry — no signup, no password.
- Customers see their tasks, mark them done, upload files, leave comments.
- Mobile-friendly. Tracked via `lastSeenPortalAt` so vendors know who's engaged.

### 3. AI layer ("Vector")

Three deployed phases, all human-in-the-loop:

| Phase | What it does |
|---|---|
| **AI Insights (per-onboarding)** | Streaming "Insights" tab on each onboarding — `headline`, `focusToday`, `focusThisWeek`, `risks`, `wins`, `nudges`, `trend`. Cached by context-hash with a 4h soft TTL. |
| **Portfolio Insights + admin dashboard** | Hero card on the home dashboard streams a portfolio-wide summary. `/admin/ai` shows cost, errors, recent calls and integration status. |
| **Miniti integration** | Webhook receiver ingests meeting transcripts → tool-use orchestrator drafts task creates / status changes → land in onboarding specific `/workflows` inbox for approve / reject / edit / assign. Match heuristic: domain → email → title → significant-word content match. |
| **Autonomous stale-task scanner** | Weekly Vercel cron + manual "Scan now" — drafts follow-up nudges for stalled tasks, scoped to each task's owner. |

Architecture:
- **Three-layer split**: deterministic JS computes signals (`tasksOverdue`, `velocity7d`, `customerEngagement`, …) → Claude does narrative reasoning over a 2–5 KB JSON snapshot → result is cached with a hash of the input state.
- **Streaming via Edge Runtime** — `client.messages.stream()` over SSE; Supabase JS client used in the edge route because Prisma's `adapter-pg` isn't edge-compatible.
- **Structured output** via `output_config.format` with a JSON schema, **prompt caching** on the system prompt.
- **Full cost observability** — every Claude call logged to an `AICall` table with input/output/cache tokens, USD cost, duration, and Anthropic `request_id` for cross-referencing.
- **Webhooks-only ingestion** (no polling), idempotent via `(source, sourceId)` unique index on `ExternalEvent`. Stuck events surface in the admin panel with a per-row reprocess button.

## Tech stack

| Layer | Choice | Notes |
|---|---|---|
| Framework | **Next.js 16** (App Router, JavaScript) | Webpack, not Turbopack (PostCSS compatibility) |
| UI | **React 19**, **Tailwind CSS v4** | CSS-first config, no `tailwind.config.js` |
| Design system | **DESIGN.md** as canonical source | `app/theme.css` autogenerated by `scripts/build-theme.mjs`; `npm run lint:ds` validates contrast and token references |
| ORM | **Prisma 7** with `@prisma/adapter-pg` | 13 models, cascade deletes throughout |
| Database | **Supabase Postgres** | Transaction pooler for app, direct pooler for migrations |
| Auth (vendor) | **Supabase Auth** | Email/password, JWT refresh in `proxy.js` middleware |
| Auth (customer) | **Magic links** | Stored in `MagicLink` table with `expiresAt` / `revokedAt` / `lastUsedAt` |
| AI | **Anthropic Claude Sonnet 4.6** via `@anthropic-ai/sdk` | Streaming, structured output, prompt caching |
| Email | **Resend** | Bounce/complaint webhook with HMAC verification |
| Drag-and-drop | **dnd-kit** | Kanban reordering and phase moves |
| Hosting | **Vercel** | Edge Runtime for streaming routes, Vercel Cron for the scanner |
| Linting | **ESLint 9** flat config | |

## Project structure

```
app/
  api/                 # 18 route groups (tasks, onboardings, insights, integrations, cron, webhooks…)
  onboardings/[id]/    # Vendor Kanban board
  portal/[onboardingId]/ # Customer magic-link portal
  admin/ai/            # Cost + integrations dashboard
  ai-drafts/           # "Vector suggests" inbox
  components/          # Feature components (TaskCard, Sidebar, TaskDrawer, …)
  ui/                  # Design system primitives (Button, IconButton, …)
  globals.css          # Tailwind + theme.css + component classes

lib/
  db.js                # ALL database access — ~25 functions, NaN-safe ID validation
  health.js            # Pure health scoring (no DB)
  ai/                  # client, context, insights, orchestrator, scan-stale, followup
  integrations/miniti.js
  supabase/            # server.js (cookies-based) + client.js (browser) + proxy.js
  portal-auth.js       # Magic-link verification

prisma/
  schema.prisma        # 13 models including AICall, ExternalEvent, PendingAIChange, Insight
  seed.js              # Seeds 10 companies with 28 tasks

scripts/
  build-theme.mjs      # DESIGN.md → app/theme.css generator
  …diagnostics
```

**One rule worth repeating**: API routes and components never call Prisma directly — everything goes through `lib/db.js`. This keeps validation (`NaN` checks, not-found returns) consistent and the schema swap-friendly.

## Getting started

```bash
# 1. Install
npm install

# 2. Configure environment
cp .env.example .env
# Fill in DATABASE_URL, NEXT_PUBLIC_SUPABASE_*, ANTHROPIC_API_KEY (for AI features)

# 3. Migrate + seed
npx prisma migrate dev
npm run seed

# 4. Run
npm run dev   # http://localhost:3000
```

Predev/prebuild hooks regenerate the design tokens (`npm run build:ds`) automatically.

### Useful scripts

| Command | Purpose |
|---|---|
| `npm run dev` | `next dev --webpack` |
| `npm run build` | `next build --webpack` |
| `npm run lint` | ESLint |
| `npm run lint:ds` | Validate DESIGN.md (contrast, broken token refs, schema) |
| `npm run build:ds` | Regenerate `app/theme.css` from DESIGN.md |
| `npm run seed` | Seed DB with sample companies and tasks |
